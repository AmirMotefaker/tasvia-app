# Tasvia Competitive Baseline — Variza

Reviewed: 2026-08-29

## Purpose

This document is a factual competitive baseline, not marketing copy. Public Tasvia claims must reflect implemented product state.

## Variza public baseline

At the review date, Variza publicly presents:
- payment links
- automatic card-to-card payment verification
- multiple bank cards/accounts
- Telegram and SMS notifications
- Excel transaction export
- QR codes
- dashboard analytics
- payment-page branding
- API and signed webhooks
- pricing/subscription tiers
- FAQ and educational blog
- developer documentation and integrations/SDKs

Primary public sources:
- https://variza.ir/
- https://variza.ir/pricing
- https://variza.ir/developers
- https://variza.ir/faq

## Tasvia public-claim policy

Every capability is classified as one of:
- Available — implemented and usable in the current product foundation.
- Preview — implemented as a non-production/demo experience or foundation.
- Planned — roadmap only; must never be described as active.

## Strategic differentiation

Variza's public proposition centers on automating card-to-card payment verification.

Tasvia's intended product boundary is broader: settlement and financial-operations infrastructure. The current repository already contains foundations for exact Money arithmetic, settlement workflow, ledger, double-entry journal, accounting intelligence and financial statements.

Tasvia should not copy Variza. It should close useful parity gaps while preserving a differentiated financial-operations architecture.
